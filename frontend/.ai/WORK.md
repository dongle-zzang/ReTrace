# Frontend current work

## WebSocket camera preview + dashboard redesign — pushed; browser/deploy verification pending

- Goal: show every camera at once. Per-camera `<img src=/mjpeg/...>` stopped at 6 cameras (browser HTTP/1.1 6-connections-per-origin limit), so the product dashboard now uses the server's single `/ws` (JPEG binary frames + `camera_status`/`detections` text). WebRTC is gone on both sides.
- Done (commit `ddca20e` on main, 2026-10-07): one socket per page (`useRealtimePreview.ts` → `realtimePreviewClient.ts`), subscribe only visible/fullscreen cards with `video:true, videoFps` (default 10, `NUXT_PUBLIC_PREVIEW_VIDEO_FPS`), 2 s reconnect + resubscribe, close on unmount/`pagehide`. `JpegFrameView` decodes offscreen one frame at a time with a single pending slot and revokes object URLs. Live `camera_status` drives card state/FPS (batched every 500 ms). Dev proxy for `/api` and `/ws` in `nuxt.config.ts`. UI: centered glass-text `online / total` hero with per-floor dot strip (click = that floor only), multi-select floor filter (all floors selected → 전체), name-only search, refresh button removed, stable scrollbar gutter.
- Verified: `npm test` 4, `npm run typecheck`, `npm run build`, `npx nuxt generate` (index.html at `.output/public/` root, no server address inside). Through the dev proxy against the real server: `/api/cameras` 25 cameras with the new fields; 7 of 8 subscribed cameras streamed simultaneously (the 8th, `3f_terrace_4k`, is offline), subscription switch and empty unsubscribe worked, 30 s socket stable. Headless Chrome screenshot showed the hero and B1 videos playing.
- Not verified: in a real browser — 6+ cameras playing at once across the whole grid, subscription change on filter/scroll, reconnect after server restart, object URL/memory release in DevTools, whether the flicker the user reported is gone. Observed ~3–7 frames/s per camera at `videoFps` 10 (camera source fps vs network unknown).
- Deployed: user uploaded the `npm run generate` output (`.output/public/` contents) to the server `frontend/` on 2026-10-07 (agent did not check the live site).
- Next: on the deployed site, check the "Not verified" items above. Later builds: `npm run generate`, then replace the server `frontend/` build files (index.html last).
- Open choices: person boxes are drawn by the server into the JPEG, so client `detections` overlay is intentionally not rendered; hero Liquid Ether colors currently include a purple (`#857bb0`) the user set.
